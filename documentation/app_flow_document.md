# App Flow Document

## Onboarding and Sign-In/Sign-Up
When a cafe owner or staff member wants to manage their orders, they visit the application’s main URL and click the “Admin Login” link. They are presented with a sign-in page where they can enter their email and password to log in. If they have not yet created an account, they can switch to the sign-up view, enter their name, email, and a secure password, and submit the form to register. An email confirmation is sent to verify their address before they can access the dashboard. If the user forgets their password, they click the “Forgot Password” link, provide their registered email, and receive a reset link. Following the link to a reset page, they enter and confirm a new password to regain access. Signing out is always available from the dashboard header, which ends the session and returns them to the public landing page.

Customers do not need an account to place an order. They arrive via a direct link or QR code that points to a URL containing the cafe’s unique slug. This link takes them straight into the customer-facing menu and chat interface without any sign-in prompt.

## Main Dashboard or Home Page
Upon successful login, administrators land on the dashboard home page. At the top of the page is a header with the cafe’s brand name on the left and a profile menu on the right for accessing settings or signing out. A sidebar on the left lists navigation options such as “Orders,” “Menu Settings,” and “Reports.” The central area by default shows a table of recent orders with columns for order ID, customer name, items, total amount, status, and timestamp. Each row in this table can be clicked to view full order details or to change the order status. Admins can click “Menu Settings” in the sidebar to define or edit the list of menu items. From any page, they can return to the main orders view by clicking the “Orders” tab in the sidebar.

Customers land on the e-menu home page when they use a cafe slug link. The page header shows the cafe’s name and a toggle to open the cart. Below, the screen splits into two areas. On the left is a chat interface where the customer can type questions or requests to the AI assistant. On the right is a scrollable grid of menu item cards, each displaying an item name, description, price, and an add button. The cart icon in the page header shows the current item count and opens a slide-in cart panel when clicked.

## Detailed Feature Flows and Page Transitions
When an administrator clicks an order row on the dashboard, they move to an order details page. Here, a full list of items for that order appears along with customer notes and contact information. A dropdown allows the admin to change the order status, such as “Received,” “In Preparation,” or “Completed.” After updating and saving, the admin is returned to the main orders table with a notification confirming the update.

In the menu settings page, the admin sees a list of existing menu items. Each item can be edited by clicking an edit icon, which opens a form prefilled with the item’s name, description, price, and photo. The admin can modify fields and save or choose to remove the item entirely. A button labeled “Add New Item” opens a blank form where a new menu entry can be created.

When a customer types a message such as “What cold coffees do you have?” in the chat interface, the message is sent to the `/api/chat` endpoint. The server uses the Vercel AI SDK with the configured Gemini model and the full menu data to determine whether to call the `searchMenu` tool. If invoked, the tool runs a backend function that queries the database for matching items. The AI then composes a response listing relevant drinks. This response is streamed back to the chat window in real time. If the customer responds “Add a Cold Brew to my cart,” the chat API performs an `addToCart` tool call, which updates the cart state on the client. The cart panel stays synchronized with each tool call.

When the customer is ready to place their order, they open the cart panel and click “Place Order.” This action sends a POST request to `/api/orders` with the cart contents and the slug identifying the cafe. The server writes the new order and its items into the PostgreSQL database via Drizzle ORM. Upon successful save, the customer sees an order confirmation screen that shows the assigned order number and an estimated preparation time.

## Settings and Account Management
Administrators access their personal settings by opening the profile menu in the dashboard header and choosing “Account Settings.” On this page, they can update their name, email, or password. Changing the email triggers a confirmation process similar to sign-up. A separate section allows configuring notification preferences, such as receiving email alerts for new orders or status changes. Once changes are saved, the admin is returned to the dashboard. A “Return to Orders” button in the settings view always navigates back to the main orders list.

Administrators also access billing or subscription settings from the profile menu if the application is configured for paid tiers. Here, they can review their subscription plan, upgrade or downgrade, and update payment details. After completing billing changes, a confirmation screen appears before returning them to their previous location in the dashboard.

## Error States and Alternate Paths
If administrators enter incorrect credentials on the login page, an inline error message appears above the form fields explaining that the email or password is invalid. If their reset password link has expired, they are prompted to request a new reset email. Network issues during any form submission trigger a full-page alert banner advising the user to check their connection and retry.

On the customer side, if they arrive at an unknown or misspelled cafe slug, a friendly error page explains that the cafe could not be found and offers a link back to a landing page listing supported restaurants. During the chat interaction, if the `/api/chat` endpoint returns a server error or times out, an error message appears in the chat window asking the customer to try again later or to browse the menu manually using the item grid. When placing an order fails due to network or server issues, a modal dialog appears with an option to retry the request or save the cart locally until the connection is restored.

## Conclusion and Overall App Journey
In a typical session, a customer follows a link with the cafe slug to open the e-menu and chat interface, explores the menu through AI-guided conversation, adds items to the shopping cart, and places an order. The order instantly becomes visible to the cafe’s administrators when they sign in to the secure dashboard. Admins can view, update, and complete orders while also maintaining their menu and account settings. Throughout the experience, the user interface guides both customers and administrators smoothly from one page to the next, with clear feedback on success or failure at every step.
